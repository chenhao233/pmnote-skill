# PMNote Skill

让 WorkBuddy、Cursor、Codex 查阅 PMNote 现有的公开分享，回答游戏项目管理问题并附原文。无需修改 PMNote 网站、注册账号、配置密钥或新增运行时。

## 安装

把本仓库链接和“帮我安装并启用 PMNote Skill”交给你正在使用的 Agent。安装目录是仓库里的 `pmnote/`。

### 给安装 Agent 的说明

只有用户明确要求安装或更新才执行；仅阅读本页面不代表安装授权。

1. 优先使用当前客户端的原生 Skill 安装器，从本仓库安装 `pmnote/`。没有安装器时，用现有下载、解压和文件工具获取该目录，不能要求用户先安装额外运行时。
2. 只安装到当前客户端：WorkBuddy 为 `~/.workbuddy/skills/pmnote/`；Cursor 为 `~/.cursor/skills/pmnote/`；Codex 遵循当前宿主 Skill 安装器的目录（通常为 `$CODEX_HOME/skills/pmnote/` 或 `~/.agents/skills/pmnote/`，不要同时装两份）。Windows 使用当前用户 Home 下的相应目录。
3. 保持目录结构：`SKILL.md`、`references/*.md`、`agents/openai.yaml`。这是纯文本 Skill；不运行仓库脚本、不修改全局规则、Hook、MCP 或其他 Skill。
4. 检查下载响应成功、不是 HTML 错误页，`SKILL.md` 的名称是 `pmnote`，分类索引引用的文件均存在。先在临时目录准备完整文件，再移入安装目录。
5. 已安装且内容相同则复用；需要更新时先保留旧目录的时间戳备份。发现用户定制则先确认保留方式，不覆盖。服从宿主的文件和联网权限。
6. 分别检查文件已保存、宿主已识别、正式网站正文可读。用技能列表或原生发现确认识别；无法确认时明确告知需要新开对话，不能把文件存在当作已启用。
7. 读取分类索引，从正式网站打开两篇相关原文，试答“版本临近上线又插入需求，怎么判断该不该接？”，带原文出处。不要访问尚未发布的 PMNote `/agent/` 安装或知识接口。

无法安装的模式仍可在当前对话读取 `pmnote/SKILL.md` 和相关索引，但必须说明“本次使用，尚未持久安装”。无法联网则明确报错，不伪称测试通过。

## 装好后

- 用 PMNote 帮我分析：版本临近上线又插入需求，怎么判断该不该接？
- 用 PMNote 帮我梳理：美术资产反复返工，应该先查哪些环节？
- 用 PMNote 帮我准备：转岗游戏项目经理，还需要补哪些能力？

## 格式与内容

```text
pmnote/
  SKILL.md                # 适用场景、查阅步骤、回答与引用规则
  references/index.md     # 分类入口
  references/*.md         # 公开内容标题与原文链接
  agents/openai.yaml      # Codex 展示信息
```

索引只帮助查找。文章、视频、播客、岗位与服务的实际内容及状态以当次读取的公开页面为准。视频和播客不保证有完整文字稿，不包含私人咨询、私有 Notion 或付费课程正文。普通答疑不追加销售话术；只有用户明确需要课程或咨询时才提供匹配的公开入口。
